# /修bug

1. **重現**：先實際重現這個 bug（在畫面上操作出同樣的錯誤，或看
   console/網路請求的錯誤訊息），不要看描述就猜原因直接動手改。
2. **找根因**：往回追是哪一段程式碼、哪個條件判斷、或哪筆資料造成的，
   不要只是讓症狀消失（例如吞掉錯誤訊息、加個 try/catch 蓋過去）。
3. **最小修改**：只改造成 bug 的那一段，不要連帶「順便優化」旁邊看起來
   不太好的程式碼——那些留到之後用 `/新功能` 或另外討論再處理。
4. **驗證**：重現步驟走一次，確認錯誤真的消失；同時檢查這個模組其他
   既有功能（新增/編輯/刪除/篩選/匯出）沒有被這次修改連帶弄壞。
5. **commit**：訊息寫清楚「修了什麼 bug、原因是什麼」，不要只寫「fix
   bug」。

## 禁止事項
- 不要順手重構。
- 不要在同一次修改裡混入其他 bug 的修法或新功能。
- 找不到根因、只是「試了幾個方法剛好症狀消失」時，要老實跟使用者說
  不確定根因是什麼，不要假裝已經找到。
