# /健康檢查

依序檢查並整理成一份摘要：

1. **Supabase 連線**：呼叫 `GET /rest/v1/vehicles?select=id&limit=1`
   （用 anon key 即可），確認回應正常（非 401/500/逾時）。
2. **各表筆數**：對業務表（`trips`/`maint`/`petty`/`billing`/`insurance`/
   `docs`/`vehicles`/`drivers`/`customers`）與流程表（`tasks`/
   `workflows`）各查一次 `select=count` 或直接數陣列長度。
3. **Storage 用量**：Supabase 後台 Storage 頁面查看 `scans` bucket 目前
   用量（沒有 API 可直接查詢用量時，註記為「請至後台確認」）。
4. **最後備份時間**：檢查本機 `localStorage` 的 `fops.lastBackupAt`（僅
   在瀏覽器內看得到）或詢問使用者上次手動備份的時間；如果超過 7 天沒
   備份，在摘要裡標記提醒。
5. **未處理的 agent_alerts**：`GET /rest/v1/agent_alerts?level=eq.action&resolved_at=is.null`
   （需要 service_role key），列出筆數與標題。
6. **未提交的 git 變更**：`git status`，列出有沒有未 commit 的檔案。
7. 整理成一份簡短摘要回報給使用者，異常項目（連線失敗、超過 7 天沒
   備份、有未處理的 action alert、有未提交變更）要特別標出來。

## 禁止事項
- 不要因為健康檢查發現異常就自己動手修（例如發現未處理的 alert 就自己
  標記已處理）——健康檢查只回報現況，處理動作交給使用者決定或另外用
  對應的指令處理。
