# /加資料表

1. **寫 schema**：仿照 `supabase/schema-v2.sql`／`schema-v3.sql` 的風格
   （`create table if not exists`、加 `created_at`），印出完整 SQL 給
   使用者到 Supabase SQL Editor 執行，等確認成功再繼續。
2. **寫 RLS**：務必啟用 `alter table ... enable row level security`，
   並用既有的 `is_admin()`/`is_active()`/`has_perm(module)` helper
   function 寫 select/insert/update/delete 政策，不要留一張沒有 RLS
   保護的表（見 `docs/decisions.md`「建表時選 Run without RLS」那條
   教訓）。
3. **前端模組**：在 `js/core.js` 的 `M` 物件加入新模組定義（`name`/
   `icon`/`fields`/`cols`，需要的話 `sum`/`unpaid`），或用獨立 `js/*.js`
   檔案（仿照 `js/workflow.js`／`js/tasks.js` 的擴充模式）。
4. **權限鍵**：決定這個模組的權限鍵名稱，補進 `PERM_OF`（如果跟模組名
   不同）；如果只有 admin 能用，加進 `ADMIN_ONLY_KEYS`。
5. **選單**：加進 `NAV_GROUPS`（或適當分組）跟 `MODLIST`（如果需要在
   帳號管理的權限勾選列表裡出現）。
6. **資料字典**：`docs/schema.md` 補上這張新表的完整欄位說明跟關聯圖。
7. **驗證**：Playwright 假登入跑過這個新畫面，確認新增/編輯/刪除/篩選
   都正常，且沒有其他模組的權限判斷被連帶影響。
8. **commit、push、回報**。

## 禁止事項
- 不要漏掉 RLS。
- 不要漏掉資料字典更新。
- 一次只加一張新表／一個新模組，不要跟其他改動混在一起。
