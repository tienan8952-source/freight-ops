# <專案名稱>

## 通知規則

執行長任務時，遇到下列情況先呼叫 `scripts/notify.ps1` 再停下等待：

- 需要使用者手動執行 SQL
- 需要使用者授權、登入、貼上金鑰
- 遇到無法自行排除的錯誤
- 整包任務全部完成（level 用 done）
- 單一階段超過 10 分鐘（level 用 info，說明進度）

Title 要具體寫「我需要你做什麼」，不要只寫「需要協助」。

## 文件維護規則

每次任務結束前，更新 `docs/工具與帳號清單.md`（或 `docs/tools/`）：
新用到的工具、新踩的坑、設定方式的變化都要補進去。

## 工作方式

一次只做一件事，不順手改別的。改動前先確認是否影響 RLS 與權限。
不新增使用者沒要求的功能、制度、名詞。
需要使用者操作時先呼叫 notify.ps1 再停下。

## 絕對不要做

把金鑰寫進任何會進 git 的檔案。
沒有備份就執行 DELETE 或 DROP。
把 repo 改成 private（如果依賴免費方案的 GitHub Pages，這會關掉 Pages）。
直接改線上資料庫的資料來修 bug。
一次改超過三個模組。

## 慣例

介面文字繁體中文。金額用 Roboto Mono。日期 YYYY-MM-DD。
新模組必須同時加：schema、RLS、權限鍵、選單、CSV 匯出、匯入對應、資料字典。
