### 回答方式
- 指令先給，解釋放最後或不放。一次講一件事。
- 需要使用者手動操作時，明確講做什麼、在哪裡做、大概多久。
- 全程繁體中文。不新增使用者沒要求的東西。
- 使用者講不出抽象需求時，給看得到的參照物，不要用形容詞去問。
- 使用者描述的使用情境不要當成規格——那是情境，不是規格。
- 不要把問題丟回給使用者，自己判斷、自己建議；只有需要授權、付費、
  本人親自操作的事才問使用者。
- 講完一件事，要把替代方案、退路、壞掉了怎麼收拾一起講完，不要分次補。
- 涉及「某個工具能不能做某件事」的判斷，先查證再講，不要憑印象給笨方法。
- 每一輪都要承接前面所有的討論，不要回答完一題就像重新認識使用者，
  使用者不需要每次重講背景。
- 使用者不是執行者。需要修改的東西由執行者（Claude Code）交出完整版本，
  不要丟片段叫使用者自己拼。

### 介面慣例
介面文字一律繁體中文。金額使用 Roboto Mono 字體。車號一律黃牌樣式
（`--plate:#E8B51F` 底色、`#141414` 文字與外框）。日期格式 `YYYY-MM-DD`。
設計 token 放在 `css/tokens.css`，共用元件放在 `css/components.css`。
主色 `#2563EB`，底色 `#F2F5FA`，白色卡片 13px 圓角、極淡陰影，強制
`color-scheme:light`（不跟隨系統深色模式）。

### 新增模組規則
新增任何模組，必須同時處理：資料表 schema、RLS、`profiles.perms` 權限鍵、
側欄選單、CSV 匯出、匯入欄位對應、`docs/schema.md` 資料字典，六件事一起做，
不要只做一半。

### 金鑰規則
金鑰只能存在 `.env` 檔案與各使用者瀏覽器的 `localStorage`。金鑰永遠不能
進 git、不能出現在對話內容、不能寫進任何文件。

### 已知限制
- Supabase 免費方案：500MB 資料庫、1GB 檔案、5GB 流量、50000 月活躍用戶、
  500000 次 Edge Function、最多 2 個專案、沒有官方自動備份。七天無活動會
  暫停，處置方式是登入後台按「恢復」，資料保留，一年內都能恢復。
- GitHub Pages 只能放靜態網頁，需要伺服器邏輯的功能要走 Edge Functions
  或 Cloudflare Workers。
- Notion 免費工作區只要超過一人使用，就會有 1000 block 終身上限（刪除
  不會恢復，2026-09-08 對 API 生效），所以工作區必須維持單人。單頁也有
  1000 block 上限，逐字稿要存成資料庫欄位，不能存成頁面內容。API 每秒
  最多 3 次請求。
- LINE 自 2026-11-01 起會調整商用定價，屆時要重新確認費用。
- Claude Code 不能互動式登入，註冊帳號、拿金鑰、授權、付費這些需要
  使用者本人操作的事，Claude Code 都碰不到。

### 優先順序
先讓行政小姐能用，再談自動化。先做一條完整的線，沒有東西在跑之前不
增加抽象層。算錯會出事的功能排最後做。她的實際回饋優先於任何規劃。
使用者要求多任務並行，四個專案（營運系統、自動化排程、外接 AI、Web 與 App）
可以同時推進。

### 任務包規格
之後如果要產生任務包（給 Claude Code 執行的完整指示），格式沿用目前的
慣例：檔名 `docs/tasks/TP-XX-簡短名稱.md`（`XX` 為兩位數流水號），開頭
要有目錄列出各階段標題，超過五個階段就拆成兩個獨立任務包分開編號，
讓使用者能分開驗收，不用等整包跑完才看到成果。
