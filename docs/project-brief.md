# 專案背景

這份是「這個專案是什麼、為誰做、目標是什麼」的主版本說明。
操作性規範（通知規則、工作方式、絕對不要做、慣例）留在 repo 根目錄的
`CLAUDE.md`；這份文件的內容不應該跟 `CLAUDE.md` 互相矛盾——`CLAUDE.md`
第一行的專案名稱「貨運行營運系統」，就是這份文件要展開講清楚的對象。

## 這是什麼

**貨運行營運系統**（repo 名稱 `freight-ops`）：給一間貨運行內部使用的
營運管理網頁系統，把原本分散在 Excel 表格、紙本單據裡的日常紀錄，集中
成一個大家共用、依權限分流的線上系統。

線上網址：https://tienan8952-source.github.io/freight-ops/

## 為誰做

貨運行內部的使用者，依角色分工：
- **司機/調度**：記錄出車報班、車輛維修進廠
- **會計**：處理零用金、客戶對帳、薪資計算、匯出報表
- **修配**：登記維修項目、費用、單據照片
- **管理員**：帳號審核與權限指派、部門管理、流程設定、系統維護
（實際角色與部門在系統內是「帳號管理」/「部門管理」頁自行設定，上面
只是目前規劃的使用情境）

## 要解決什麼問題

原本靠 Excel／紙本記錄容易遇到：資料散落在不同人電腦裡對不起來、
沒有統一的照片憑證存放方式、保險/證照到期靠人工記得容易漏、對帳跟
維修費用誰付了誰沒付要翻好幾份表才知道、新流程需要簽核時沒有留下
處理紀錄。這個系統把這些流程整合進同一個地方，並用權限控制「誰看得到
什麼」。

## 目標與範圍

**做的事**：出車報班、車輛維修、零用金、客戶對帳、保險/證照到期提醒、
公文合約建檔、檔案庫、工作單簽核流程、薪資計算、帳號與部門權限管理、
Excel/CSV 資料匯入、備份與還原、Claude Code 主動回報機制、列印與鍵盤
快捷等使用效率功能。完整模組清單見 [schema.md](schema.md)。

**不做的事（目前）**：不做行動裝置推播通知（規劃中，見
[tools/line-messaging-api.md](tools/line-messaging-api.md)）、不做
自然語言輸入（見 [decisions.md](decisions.md)「為什麼快速新增用按鈕而非
自然語言輸入框」）、不做多公司/多租戶（目前設計上是單一貨運行內部使用）、
不做伺服器端排程任務（見
[tools/supabase-edge-functions.md](tools/supabase-edge-functions.md)）。
