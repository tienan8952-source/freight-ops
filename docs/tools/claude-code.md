# Claude Code

## 1. 這個專案用它做什麼
這個專案主要的開發工具：寫程式、跑 git、寫 SQL schema、本機驗證功能、
維護文件，幾乎所有開發工作都透過它執行。

## 2. 目前的設定
- 專案內的行為規則寫在 repo 根目錄的 `CLAUDE.md`：通知規則（什麼情況要
  呼叫 `scripts/notify.ps1` 回報）、文件維護規則（任務結束前更新
  `docs/工具與帳號清單.md`），以及本次任務新增的工作方式／絕對不要做／
  慣例三節
- 指令庫：`.claude/commands/`（見 `docs/tools/README.md` 與
  `docs/index.md` 的說明，內容見階段 I）
- 專案助手：`.claude/agents/`。目前有需求分流、RLS 與權限檢查、實際操作
  驗收三個助手；全部先讀 `docs/briefs/00-總控.md`，預設唯讀，結果交回
  Claude Code 統一處理，不形成助手互相交接的工作鏈。
- 金鑰放哪：不需要額外金鑰，使用者用自己的 Claude 帳號登入

## 3. 常用操作
- 一般開發：直接在對話裡描述需求，讓它讀 `CLAUDE.md` 跟現有程式碼後動手改
- 用指令庫裡的斜線指令做固定流程，例如 `/新功能`、`/修bug`、`/部署`、
  `/健康檢查`、`/交接`（見 `.claude/commands/`）
- 需求歸屬不明、要核對 RLS／權限完整性、或要做行政小姐操作驗收時，
  Claude Code 可依 `.claude/agents/` 裡的 description 自動委派對應助手。
- 需要它主動回報進度／等待人工處理時，它會呼叫：
  ```powershell
  .\scripts\notify.ps1 -Level action -Title "需要你做什麼" -Body "說明"
  ```

## 4. 踩過的坑
- 目前沒有專屬於 Claude Code 這個工具本身的重大事故；跟它互動時真正
  踩過的坑（PowerShell 執行原則、gh PATH、Supabase 401 等）都記在對應
  工具自己的文件裡，這裡不重複列。
- 比較值得注意的是「一次改太多」的風險：早期任務包如果一次要求做的
  事情太多、太雜，容易漏掉驗證或悄悄動到不該動的邏輯，因此後續在
  `CLAUDE.md` 補了「工作方式」一節（一次只做一件事、不順手改別的）。
- `.claude/` 原本整個被 `.gitignore` 排除；若只新增助手檔卻不調整例外規則，
  助手不會進 git。現在只追蹤 `.claude/agents/*.md`，既有本機指令仍維持忽略。

## 5. 限制與風險
- 它看到的專案狀態僅限於這台電腦上的檔案與已執行過的指令結果，換一台
  電腦要重新讓它讀過一次專案（`CLAUDE.md`、schema、程式碼）才能維持
  一致的判斷。
- 沒有記憶跨對話的隱性上下文，重要決策與踩過的坑務必寫進文件（
  `docs/decisions.md`、各工具手冊），不要只放在對話紀錄裡。
- 實際操作驗收助手只放行啟動本機靜態伺服器的 Bash 命令及 Playwright
  操作，不開放一般 shell、git、部署或依賴安裝；沒有安全測試資料時只能
  做唯讀驗收。
