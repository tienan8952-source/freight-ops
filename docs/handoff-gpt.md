# GPT 交接說明

> 這份文件是給使用者貼到 GPT 專案用的，只寫這四節，不寫語氣或風格規矩。

## 一、GPT 產出時要附上的四件事

1. 想解決什麼問題，用使用者原本的話描述，不要美化。
2. 想到的做法，可以有多個方向，不用挑定一個。
3. 這個想法會碰到哪些現有的東西（哪張表、哪個畫面、哪個既有流程），
   不確定就寫不確定，不要用猜的當成事實。
4. 哪些是使用者明確說過的、哪些是 GPT 自己推論補上的，要分開標示清楚。

## 二、GPT 不要做的事

- 不要直接產出 SQL 或程式碼。
- 不要替使用者決定優先順序。
- 不要把使用者舉的例子當成範圍上限。
- 不要新增使用者沒提過的功能或名詞。
- 不要回答完一個問題就忘記前面的討論。

## 三、GPT 看不到什麼

GPT 看不到 repo，看不到 Supabase 的實際表結構。涉及現有結構的推論一律
標明是推測，交給 Claude 核對是否正確。

## 四、這個專案的固定前提

- Supabase 免費方案有容量與流量上限、七天無活動會暫停。
- GitHub Pages 只能放靜態網頁。
- 金鑰不能放前端。
- 介面全繁體中文。
- 先讓行政小姐能用，再談自動化。
