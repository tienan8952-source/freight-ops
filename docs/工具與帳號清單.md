# 工具與帳號清單

記錄這個專案實際用到的所有工具與帳號設定。**每次任務結束前都要回來更新這份文件**（新工具、新踩的坑、設定方式變了都要補進來）。

## Supabase

- **做什麼用的**：整個系統的後端——資料庫（Postgres）、登入註冊（Auth）、照片/檔案（Storage）、REST API。
- **我們怎麼設定的**：
  - Project URL：`https://ekzqrpgrxicyvaqagdjp.supabase.co`
  - 資料庫 schema 依序在 Supabase 後台 SQL Editor 貼上執行：`supabase/schema-v2.sql` → `supabase/schema-v3.sql`
  - 前端（`js/core.js`）直接用 anon key 打 REST API，沒有用 supabase-js SDK
  - `scripts/notify.ps1` 用 service_role key 寫入 `agent_alerts` 表（繞過 RLS，讓 Claude Code 可以主動回報）
- **金鑰放哪（只寫位置）**：
  - anon key：寫在 `js/core.js` 檔案開頭的常數（這把本來就設計成可公開，靠 RLS 擋權限）
  - service_role key：`.env`（repo 根目錄，已列在 `.gitignore`，只能留在本機，絕對不能提交）
- **踩過的坑**：
  1. **帳號註冊順序**：一開始就讓人在畫面上「註冊」，但那時候建立 `profiles` 資料列的 schema/trigger 還沒佈署好，導致註冊完 `auth.users` 有資料、但 `profiles` 沒有對應那一列，登入時系統找不到 profile，整個卡住登不進去。**教訓：一定要先把 schema（含 profiles 的建立邏輯）部署完成，才能開放讓人開始註冊**；如果已經有帳號卡在這個狀態，要手動去 `profiles` 表幫他補一列。
  2. **Supabase Site URL 預設 localhost**：Auth 的 Site URL 預設是 `http://localhost:3000`，註冊後寄出的驗證信裡的連結會指向 localhost，使用者點了打不開，等於驗證信失效。**要到 Supabase 後台 Authentication → URL Configuration，把 Site URL 改成正式網址** `https://tienan8952-source.github.io/freight-ops/`。
  3. **notify.ps1 被擋（401）**：用 service_role key 直接呼叫 REST API 時，Supabase 會偵測「看起來像瀏覽器」的請求並擋掉 secret key，要在 `Invoke-RestMethod` 明確帶一個非瀏覽器的 `-UserAgent`（見 `scripts/notify.ps1` 裡的註解和寫法）。
- **下次要改去哪裡改**：
  - Schema 改動：改 `supabase/*.sql`，改完貼到 Supabase 後台 SQL Editor 執行
  - Site URL / 驗證信設定：Supabase 後台 → Authentication → URL Configuration
  - anon key 要換：改 `js/core.js` 開頭的常數
  - service_role key 要換：改本機 `.env`

## GitHub

- **做什麼用的**：程式碼版本控制與遠端備份。Repo：`tienan8952-source/freight-ops`。
- **我們怎麼設定的**：本機 git remote `origin` 指到 `https://github.com/tienan8952-source/freight-ops.git`，用 HTTPS + gh CLI 管理的憑證做認證。
- **金鑰放哪**：由 `gh auth login` 管理，存在 Windows 認證管理員（keyring），不在 repo 裡。
- **踩過的坑**：
  1. **免費帳號改成 private 會關掉 GitHub Pages**：GitHub Free 方案的 Pages 只支援 public repo；如果把這個 repo 改成 private，Pages 網站會直接失效（要 Pro/Team/Enterprise 才能在 private repo 用 Pages）。今天評估過是否要改 private，最後決定維持 public，就是因為這個限制。
- **下次要改去哪裡改**：
  - repo 可見度/設定：`gh repo edit tienan8952-source/freight-ops`（**改 private 前一定要先確認 Pages 還要不要用**）
  - 遠端網址：`git remote -v` 或 `.git/config`

- **我們怎麼設定的**：網址 `https://tienan8952-source.github.io/freight-ops/`，來源是 GitHub repo Settings → Pages 設定的 branch/資料夾（main 分支根目錄）。
- **金鑰放哪**：無。純靜態網站，前端只帶 Supabase anon key，本來就是設計成可公開的。
- **踩過的坑**：跟上面「GitHub」同一條——private repo 在免費方案下會讓 Pages 失效。
- **下次要改去哪裡改**：GitHub repo → Settings → Pages（改發布來源）；網站原始檔就是這個 repo 的 `index.html` / `js/*.js`，改完 push 到 main 幾分鐘內會自動重新發布。

## gh CLI

- **做什麼用的**：在終端機直接操作 GitHub（repo 設定、以後可能開 PR/issue），不用開瀏覽器。
- **我們怎麼設定的**：`gh auth login` 登入 `tienan8952-source` 帳號，登入狀態存在本機。
- **金鑰放哪**：gh 自己管理的 token，存在 Windows 認證管理員（keyring），不在 repo 裡。可用 `gh auth status` 確認登入狀態。
- **踩過的坑**：**裝好但 PATH 沒刷新**——用安裝程式裝完 gh 之後，當下已經開著的終端機視窗還吃不到新的 PATH，執行 `gh` 會找不到指令；要開一個新的終端機視窗（或重新登入/重開機）才吃得到新 PATH，不是沒裝好。
- **下次要改去哪裡改**：先跑 `gh --version` 確認有沒有裝好；如果指令找不到，先試著開一個新終端機視窗，不要急著重裝。

## Claude Code

- **做什麼用的**：這個專案主要的開發工具——寫程式、跑 git、寫 SQL schema、本機驗證功能都靠它執行。
- **我們怎麼設定的**：`CLAUDE.md` 定義了通知規則，規定什麼情況要呼叫 `scripts/notify.ps1` 主動回報進度或卡住的狀況。
- **金鑰放哪**：不需要額外金鑰，用的是使用者自己的 Claude 帳號登入。
- **踩過的坑**：暫無特別踩坑，主要靠 `CLAUDE.md` 的通知規則讓任務中斷點/完成都會主動回報，不用一直等著問。
- **下次要改去哪裡改**：通知規則寫在 `CLAUDE.md`；要調整什麼情況該通知、通知內容格式，直接改那份檔案。

## Node / npm

- **做什麼用的**：本機驗證/工具用途（例如用 `npx playwright` 開瀏覽器截圖驗證畫面）。正式站台本身是純靜態 HTML/JS，不需要 build 流程。
- **我們怎麼設定的**：沒有專案自己的 `package.json`/固定依賴，需要工具時用 `npx <套件名>` 現抓現用。
- **金鑰放哪**：無。
- **踩過的坑**：**PowerShell 執行原則擋住 npm**——npm 在 Windows 上是靠 `npm.ps1` 這支 PowerShell script 執行，預設的執行原則（Restricted）會擋掉，一跑 `npm`/`npx` 就會出現「因為在此系統上停用了指令碼執行，所以無法載入」的錯誤。解法：跑 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 永久放行（單次應急可以用 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`，只在當次視窗有效）。
- **下次要改去哪裡改**：又看到「已停用指令碼執行」的錯誤時，就是這個問題，用上面的 `Set-ExecutionPolicy` 指令處理，不用重裝 Node。
