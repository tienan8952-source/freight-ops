# 重建指南：換一台新電腦，從零到能繼續開發

給沒碰過這個專案、但要在一台全新電腦上接手開發的人。照著做完應該就能
繼續改程式、commit、push、部署。

## 1. 需要先有的帳號權限
- GitHub 帳號 `tienan8952-source` 的存取權限（或已被加為 collaborator）
- Supabase 專案（`ekzqrpgrxicyvaqagdjp`）的登入權限（Project 的
  Owner/Member）
- 能取得 `.env` 裡 `SUPABASE_SERVICE_KEY` 的值（去 Supabase 後台重新
  複製，不要跟舊機器的檔案互傳，見 `docs/env.md`）

## 2. 安裝工具
1. Git（含 Git Bash）
2. Node.js（用來跑 `npx playwright` 之類的本機驗證工具，不是給正式站台
   用的）
3. GitHub CLI（`gh`）：安裝完**開一個新的終端機視窗**再用（見
   `docs/tools/gh-cli.md`「PATH 沒刷新」的坑）
4. PowerShell 執行原則：確認 `Get-ExecutionPolicy -Scope CurrentUser`
   不是 `Restricted`，需要的話執行
   `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

## 3. 取得程式碼
```bash
git clone https://github.com/tienan8952-source/freight-ops.git
cd freight-ops
```

## 4. 登入 GitHub CLI（互動式，必須自己手動做）
```bash
gh auth login
```
照畫面指示選 GitHub.com → HTTPS → 瀏覽器登入。完成後 `gh auth status`
應該顯示已登入 `tienan8952-source`。

## 5. 設定本機金鑰
在 repo 根目錄建立 `.env`（已被 `.gitignore` 排除，不會進 git）：
```
SUPABASE_URL=https://ekzqrpgrxicyvaqagdjp.supabase.co
SUPABASE_SERVICE_KEY=<去 Supabase 後台 Project Settings → API 複製 service_role secret key>
```
確認格式是兩行、`=` 後面沒有多餘空白，`SUPABASE_SERVICE_KEY` 對應到的
是 `service_role`（secret）key，不是 `anon`/`publishable` key（曾經
搞混過，見 `docs/tools/supabase.md`）。

## 6. 驗證環境可以動
```bash
git status                     # 應該顯示乾淨、在 main 分支
.\scripts\notify.ps1 -Level info -Title "測試" -Body "重建環境驗證"
```
如果送出成功（顯示「已送出通知：[info] 測試」），代表 `.env` 設定正確、
PowerShell 可以正常執行 script。

## 7. 本機預覽網站（不需要 build）
```bash
python -m http.server 8091
# 瀏覽器打開 http://localhost:8091/index.html
```

## 8. 讓 Claude Code（或自己）讀懂專案
按 `docs/index.md` 的建議順序看一輪：`README.md` → `docs/index.md` →
`docs/工具與帳號清單.md` → `docs/schema.md`；如果是要接續某個未完成
的任務，先看 `.claude/commands/交接.md` 產生的狀態摘要（如果有上一次
留下的的話）。

## 9. 之後的開發流程
一般改動走 `.claude/commands/新功能.md`／`修bug.md`；部署走
`.claude/commands/部署.md`（commit → push → 確認線上 HTTP 200）。
