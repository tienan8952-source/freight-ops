跟 [CHANGELOG.md](CHANGELOG.md) 的差異：CHANGELOG 是逐 commit 的一行清單，
這份是「發生了什麼、為什麼、卡在哪、怎麼解決」的故事版本，資料來源是
`git log --oneline --all`、`docs/decisions.md`、`docs/incident.md`、
`docs/tools/` 底下各工具的「踩過的坑」，以及 `agent_alerts` 表裡當天留下

## 上午：從零建立系統骨架（12:43–13:53）

- **12:43** `Initial commit: freight ops system UI`——最早的介面雛型
  進 repo。
- **13:12** 階段一：帳號與權限的 RLS schema（`schema-v2.sql`）先寫好、
  部署到 Supabase。
- **13:17** 階段二/三：登入註冊、權限分流、帳號管理後台完成。這個階段
  附近踩到兩個跟「帳號能不能順利進得去」有關的坑（時間點以問題本質
  推斷，非精確對應到單一 commit）：
  - **先開放註冊、才把 `profiles` 表建好**：導致最早幾筆註冊的帳號
    只有 `auth.users` 資料、沒有對應的 `profiles` 資料列，登入時系統
    找不到帳號資料。解法：補齊 schema 後，手動幫卡住的帳號補一筆
    `profiles`（SQL 見 `docs/incident.md`「登入不了」一節）。
  - **Supabase Auth 的 Site URL 預設 `localhost:3000`**：註冊驗證信裡
    的連結指向 localhost，點了打不開。解法：改到正式的 GitHub Pages
    網址；另外也遇到驗證信 10 分鐘就過期來不及點的狀況，用
    `update auth.users set email_confirmed_at = now()` 手動標記已驗證
    繞過（詳見 `docs/tools/supabase.md`）。
- **13:43** 階段零：v3 資料庫 schema（部門/流程/工作單/通知/檔案庫/
  agent alerts）一次補齊，這一版把後面幾個階段共用的資料表都準備好。
- **13:51** 重構：把主程式拆成 `js/core.js`，`render()` 改成可擴充的
  模組 dispatcher，順便修了幾個小地方（複製上一筆、金額千分位、本月
  比較、手機按鈕尺寸）。這一步是為了讓後面每個階段能用「擴充點」
  （`BOOT_HOOKS`、`navBadge`、`myTaskCard` 這類 `typeof` 檢查後才呼叫的
  掛勾）疊加功能，而不用每次都改動核心檔案。
- **13:53** 階段一/二：照片改存 Supabase Storage（含一次性搬移工具）、
  系統維護頁的備份/匯出Excel/還原。背後的問題是：**照片一開始直接轉
  base64 存進資料表欄位，資料庫容量很快就撐大**，改成只存 Storage 路徑
  字串後解決（`docs/decisions.md` 有記這條決策的完整理由）。

## 收尾與環境debugging（14:19–14:23）

系統功能做完後，換成處理「工具本身」的問題：

- **PowerShell 執行原則擋住 npm**：跑 `npm`/`npx` 相關指令時出現指令碼
  被停用的錯誤，執行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
  解決（也曾用 `-Scope Process -ExecutionPolicy Bypass` 做單次應急）。
- **gh 安裝後 PATH 未刷新**：新裝的 `gh` CLI 在當下的終端機視窗抓不到，
  短期用完整路徑呼叫、或開新視窗解決；另外 `gh auth login` 是互動流程，
  這件事一定要使用者自己手動做一次，Claude Code 的非互動 shell 跑不了。
- **14:23** `fix: notify.ps1 明確帶非瀏覽器 User-Agent`——`notify.ps1`
  直接用 service_role key 打 REST API 時被 Supabase 判定為「看起來像
  瀏覽器的 secret key 請求」擋下（401），修正後加上自訂 User-Agent
  解決。

## 為什麼維持 repo public

開發過程中評估過要不要把 `tienan8952-source/freight-ops` 改成
private（多一層保護），但 GitHub Free 方案的 Pages 只支援 public repo，
改 private 會直接讓線上網站失效；權衡後決定維持 public，完整理由見
`docs/decisions.md`。

## 額外發現（不在本次任務範圍內，但值得記錄）

在查詢 `agent_alerts` 表協助寫這份文件時，發現目前透過
`scripts/notify.ps1`（從 Bash 呼叫 `powershell.exe` 執行）送出的中文
標題／內容，寫進 Supabase 後會變成亂碼（例如「測試通知」變成
「????」）。初步判斷可能是 Windows PowerShell 5.1 預設主控台編碼
（系統 ANSI/區域碼頁）跟 UTF-8 之間轉換時遺失資訊，而不是 Supabase
或資料表本身的問題。這件事會影響「執行紀錄」頁面管理員看到的通知
內容可讀性，但**不影響通知機制本身是否成功送達**（`level`／
`resolved_at`／`session`／時間戳記都正常）。這個問題不在本次任務範圍
內，未修正，留給之後處理 `notify.ps1` 時一併解決（例如在腳本裡明確
指定 UTF-8 輸出編碼，或改用 UTF8 位元組陣列送出 JSON body）。
